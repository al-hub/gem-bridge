프로젝트 개요 및 목적 (Project Purpose)

gem-bridge는 모바일 Gemini 앱이나 Google Drive 동기화 폴더에서 발행된 태스크 명세를 실시간 감지하여, 로컬 워크스페이스(WSL2) 환경의 코드를 안전하게 반영하고 원격 Git 저장소에 자동 Commit & Push를 수행하는 Google Workspace ↔ Git 자동화 파이프라인 데몬입니다.

모바일 원격 주도 개발
PC 환경에 직접 접속하지 않고도 모바일 Gemini 앱으로 태스크 파일을 드라이브에 생성하여 자동 코드 수정 및 Push를 수행합니다.
안정적인 백그라운드 상주
Linux systemd 서비스 데몬으로 등록되어 파일 I/O 이벤트(Polling Loop / Inotify)를 무중단 감시합니다.
무결성 및 격리 아카이빙
가상 파일(.gdoc) 필터링, 에러 방지 처리 및 완료된 작업 파일의 processed/ 자동 이동으로 멱등성을 보장합니다.

전체 동작 구조 및 아키텍처 (Architecture)

gem-bridge는 모바일 입력 계층, 동기화 감시 계층, 코드 처리 계층, Git 버전 관리 계층으로 분리된 비동기 이벤트 파이프라인 구조를 갖습니다. 

┌─────────────────────────────────────────────────────────────────────────────┐
│                          1. 모바일 / Gemini 클라이언트                      │
│       - 스마트폰 Gemini 앱 또는 Google Drive 웹/앱에서 작업 명세 작성       │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │ Cloud Sync (Google Drive Desktop)
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                2. 마운트 폴더 감시 (WSL /mnt/g/.../GeminiBridge/)           │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                   gem-bridge 데몬 (bridge_daemon)                   │   │
│   │   - 파일 이벤트 감시 (Polling Loop / File Watcher)                  │   │
│   │   - .gdoc 가상 링크 파일 필터링 ([Errno 5] 방지)                    │   │
│   │   - 실질 텍스트 파일(.txt, .md, .json) 파싱 및 명령 추출            │   │
│   └──────────────────────────────────┬──────────────────────────────────┘   │
└──────────────────────────────────────┼──────────────────────────────────────┘
                                       │
              ┌────────────────────────┴────────────────────────┐
              ▼                                                 ▼
┌─────────────────────────────────┐           ┌───────────────────────────────┐
│     3. 로컬 소스코드 작업 반영  │           │      4. Git 자동화 파이프라인 │
│ - 타깃 저장소 소스 파일 수정    │           │ - 변경 파일 인덱싱 (git add)  │
│ - 템플릿 생성 및 리팩토링 검증  │           │ - 유의미한 커밋 생성 및 Push  │
└────────────────┬────────────────┘           └───────────────┬───────────────┘
                 │                                             │
                 └──────────────────────┬──────────────────────┘
                                        ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        5. 태스크 완결 및 안전 아카이빙                      │
│            - 처리 완료된 명세 파일을 GeminiBridge/processed/ 폴더로 이동     │
└─────────────────────────────────────────────────────────────────────────────┘
WSL 마운트 I/O 주의사항: Google Drive Desktop이 생성하는 .gdoc 포인터 파일은 Linux 환경에서 직접 읽을 시 [Errno 5] Input/output error가 발생할 수 있습니다. gem-bridge는 이를 자동 감지 및 건너뛰며, 실제 텍스트 내용(.txt, .md, .json)만 안전하게 수집합니다.

설치 및 환경 설정 (Installation & Setup)

1) 사전 준비 사항

  • 운영체제: Windows WSL2 (Ubuntu 20.04/22.04 LTS 이상)
  • 연동 드라이브: Windows Google Drive for Desktop 실행 및 WSL 마운트 경로 확인 (예: /mnt/g/My Drive/GeminiBridge/)
  • 런타임: Python 3.10 이상 및 Git SSH/PAT 인증 완료 환경

2) 소스 클론 및 종속성 설치

# 저장소 클론
git clone https://github.com/al-hub/gem-bridge.git ~/workspace/gem-bridge
cd ~/workspace/gem-bridge

# 가상환경(선택) 또는 필수 패키지 설치
pip install -r requirements.txt

3) 설정 파일 및 폴더 구조 준비

# 예제 설정 복사 및 실제 경로 수정
cp config.example.json config.json

# 감시할 Google Drive 폴더 및 아카이브 경로 생성
mkdir -p "/mnt/g/My Drive/GeminiBridge/processed"

4) systemd 데몬 등록 및 실행

# 서비스 파일 시스템 등록
sudo cp gem-bridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gem-bridge.service

# 데몬 구동 상태 및 실시간 로그 모니터링
sudo systemctl status gem-bridge.service
journalctl -u gem-bridge.service -f

사용 방법 및 워크플로우 (Usage Workflow)

  1. 태스크 발행: 모바일 스마트폰이나 웹 브라우저의 Google Drive GeminiBridge/ 폴더에 작업 내용이 담긴 텍스트 파일(예: task_20260408_01.txt)을 업로드하거나 작성합니다.
  2. 데몬 감지: 상주 중인 gem-bridge 데몬이 파일 유입을 실시간 감지하여 포인터 여부를 판별하고 내용을 파싱합니다.
  3. 코드 수정 및 검증: 명세서에 지시된 워크스페이스 내 대상 파일에 변경 사항을 정확히 적용합니다.
  4. Git Commit & Push: 수정 사항을 스테이징(git add)하고 자동 커밋 메시지를 생성하여 원격 저장소의 메인 브랜치로 자동 Push합니다.
  5. 완료 아카이빙: 처리가 완료된 태스크 파일은 중복 실행 방지를 위해 GeminiBridge/processed/ 디렉터리로 즉시 이동 격리됩니다.

유지보수 및 제거 (Maintenance & Uninstallation)

1) 최신 버전 업데이트

cd ~/workspace/gem-bridge
git pull origin main
pip install -r requirements.txt
sudo systemctl restart gem-bridge.service

2) 서비스 완전 제거 (Uninstall)

# 1. systemd 서비스 중지 및 자동 시작 해제
sudo systemctl stop gem-bridge.service
sudo systemctl disable gem-bridge.service

# 2. 서비스 정의 파일 삭제 및 systemd 리로드
sudo rm /etc/systemd/system/gem-bridge.service
sudo systemctl daemon-reload
sudo systemctl reset-failed

# 3. 로컬 프로젝트 디렉터리 정리 (필요시)
rm -rf ~/workspace/gem-bridge
